# 配置与仓库边界

## 无个人身份的默认安装

发布源码不再把原作者 QQ 号、某个群号、Q-API 业务介绍或特定模型供应商作为默认权限、路由和人设。新安装的所有者、成员观察群来自显式配置；未提供所有者时无人获得所有者权限，未配置成员观察群时不轮询陌生群。工具仍默认 `full`，不是 Lite，也未删除记忆、任务、文件、QQ 或虚拟机能力。

| 配置 | 用途 |
|---|---|
| `deployment.web_port` / `deployment.onebot_port` | 安装器首次保存的本机端口，旧配置缺失时仍用 6185/6199；显式 `BOT_WEB_PORT` / `BOT_ONEBOT_PORT` 仅临时覆盖。用 `info` 查配置地址、`up` 应用变更，不必每次重新导出。 |
| `HIGAN_ROOT` | 所有持久状态的共同绝对目录；未设置时为当前系统账号的 `~/higan`。root 账号自然仍使用旧 `/root/higan`，不扫描、复制或迁移其它账号数据。 |
| `HIGAN_SETTINGS_FILE` | 显式外部 JSON 配置；密钥、人设、所有者列表不放进源码。已有配置原样保留，不自动补个人身份。 |
| `owner_qqs` / `HIGAN_OWNER_QQS` | 所有者 QQ 的字符串数组；优先私有配置文件。空列表不授予所有者权限。 |
| `member_watch_groups` / `HIGAN_MEMBER_WATCH_GROUPS` | 明确选择的成员观察群字符串数组；空列表不等于所有群。 |
| `onebot` / `HIGAN_ONEBOT_BASE`、`HIGAN_ONEBOT_TOKEN` | 可选 OneBot 服务与凭据；配置文件中只有显式启用才连接。使用既有本地兼容地址的旧部署可继续覆盖地址。 |
| `HIGAN_VM_BRIDGE_BASE` | 虚拟机桥接 HTTP(S) 服务地址；默认仍为旧本机兼容端口，部署者可以覆盖。群操作必须给出目标群或来自当前群上下文，不再回退到作者群号。 |
| `ASTRBOT_ROOT` | 已有 AstrBot 实例根目录；未设置时按实际工作目录定位，不猜测开发机路径或任意品牌模型。 |
| `HIGAN_DASHBOARD_URL` | 本地命令管理工具的面板地址；允许选择不同的数字 loopback HTTP 端口，不允许凭据被发送到远程地址、代理或重定向目标。 |

环境变量中的列表使用 JSON 数组；例如 `[]` 表示明确的空集合。设置文件优先，非法配置报错而不是扩大权限。只有已配置的模型或唯一无歧义的私有模型可被选中；不再按原作者供应商名称偷偷回退。

**兼容边界：**本次没有部署生产，未改任何现有私有文件。过去只依靠源码里个人身份默认值的旧安装，在更新前必须把自己的所有者和观察群显式保存到配置。不能为了“兼容”继续向每个新用户授予同一批个人账号权限。插件源码改变后，既有受控安装的镜像 hash 防护仍然生效；本次不绕过更新检查或迁移旧状态。

## 哪些固定值不是个人硬编码

容器内挂载路径、默认可覆盖的本机端口、协议字段、QQ ABI 名称、固定依赖版本、网络保留地址段和测试用合成 ID 属于接口/可复现性约束，不应随意删除。完整上游 AstrBot 位于 `vendor/`，原始 hash、许可证、功能和声明保留，不对其中厂商链接进行批量替换。

## 不属于当前发布入口的内容

- 未被现行代码调用的两份旧提示词包含个人群和 Q-API 业务设定，已连同原内容移入 [个人运维归档](../trash/20261030-personal-operations/README.md)，不再进入插件镜像。
- 绑定个人服务器目录、服务和数据库的旧发布/配置工具移入同一归档；它们不是通用安装器，不能照抄用来更新自己的或生产实例。
- 历史证据在 [证据目录](evidence/README.md)，不作为默认配置；更旧的一次性修补保存在 `trash/`，不删除文件、不据旧报告执行操作。Git source archive 已排除 `trash/`，Docker build context 也排除它。

当前安装入口只有根目录双击 Windows 向导和 Linux shell 入口，共同调用 `tools/bootstrap.py`；仓库外层的其它业务工程不属于本 bot 发布包。
