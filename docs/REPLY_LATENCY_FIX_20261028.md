# 回复延迟修复（2026-10-28）

## 实测，不能混淆的口径

线上最近 60 分钟采样 47 次请求，现有 `model_latency` 中位数 19.174 秒，
最小 3.942 秒、最大 252.418 秒。该指标包含线程调度和非流式 HTTP 完整响应，
不是纯推理时间或首 token 时间，也不包含上下文准备、排队、工具和发送。
请求输入 token 中位数 78927、范围 13170–87234。系统内存仍有约 5.8GB 可用，
不能把现有慢回复归因于已证实的内存耗尽。采样不是受控的整体前后性能对照。

## 增量修复

- 原 `load_record_snapshot` 每次扫描完整 JSONL，8 个公开群档案逐一解析，
  当前会话的活动时间读取还会再次读取同一档案。
- 新增每个 Recorder 实例的读缓存，按设备、inode、长度和纳秒修改时间核验。
  文件未变直接返回脱离内部缓存的深复制；标准追加只解析最后完整换行之后的部分。
  无换行尾行是暂定状态，下次追加会重新读取，避免重复计数或丢行。
- 改筛选、扩大窗口、截短、替换和同长度重写会重新扫描。每个路径只保留基础查询
  与最近一个带排除条件查询，活动时间读取不会挤掉共享窗口查询。
- 当前消息排除 ID 每轮变化时，当前群仍重新扫描；其他群可复用。没有增加
  无界全量消息 ID 索引。缓存按既有 append-only 归档契约工作，同 inode 重写前缀
  又增长文件不能仅凭 stat 证明是追加；不得把任意外部原地重写视为受支持写入方式。
- 统一历史快照与本轮图像转换移至 `asyncio.to_thread`，仍由同一 FIFO 执行锁持有
  本轮所有权。不是并行跑两个模型，不跳过权限或消息顺序。
- 图像转换在线程返回后再更新转录；失败不部分改写模型消息。相同路径的新截图
  仍会重新读取，不能用 URL／路径永久缓存偷换新像素。
- 增加无正文、无群号的阶段日志：锁等待、整轮、历史快照、上下文、图像准备。
  原有模型网络耗时日志保留。需要后续自然消息采样才能判定端到端变化。

## 边界

不删除历史、记忆、图片、任务或工具，不调整模型及推理参数，不设置强制短回答，
不截断正在执行的后台任务。较大的模型输入、后台整轮持锁和上游长请求仍需继续测量。
