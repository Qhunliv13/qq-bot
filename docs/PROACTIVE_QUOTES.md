# 主动引用与原生消息目标

本次修复的是**模型主动选择的 QQ 原生引用**丢失，不是让每条回复自动引用触发消息，也不是网页文章/搜索引用。

## 正确协议

- `reply_to` 只表示回答哪几条**当前批次**消息；不能用历史消息伪造当前输入。选中最新输入时，仍不会默认加引用框。
- 模型需要主动引用时，可在公开正文开头使用 `[quote:实际原生消息号]`，包括最终 JSON 的 `text` 字段或 `reply_now.text`。
- 引用目标必须是当前原始消息，或**发送目标同一会话**的历史原始 `record.id`；共享上下文中看见别群消息不代表能在当前群引用它。正文中的 `#1234`、任务 ID、记忆 ID 或嵌套引用对象均不能建立引用授权。
- 自主发言没有当前人类输入：保持 `reply_to: []`；最终公开发言仍需显式 `delivery: "new"`。引用只是正文的可选传输控制，不放松公开发送、群策略或权限约束。
- 行内、代码块或引号中的引用示例保留字面内容；不将普通解释句猜成引用操作。不设置固定话术、不强制模型必须引用。

例：当前消息号是 `1234`，模型明确选择引用同一会话历史原始消息 `8101` 时：

```json
{"reply_to":["1234"],"text":"[quote:8101]这里是公开回复正文。"}
```

自主机会中选定同一条历史消息时：

```json
{"reply_to":[],"text":"[quote:8101]这里是模型自行选择的公开更新。","delivery":"new"}
```

这些数字只演示格式，不是安装器预置的真实消息号。未授权/无效的原生引用控制被移除，不猜替代目标；回复归属仍单独校验。旧的纯文本传输入口保持原有兼容行为，本次主要修复现代结构化模型回路，不把兼容入口视为扩大历史授权。

## 修复原因

原结构化解码器会无条件移除正文中的引用控制；`reply_now` 又总是经过结构化封装，因此主动引用无法进入原生 `Reply` 组件。自主最终发送还没有转发解码后的引用元数据；持久任务最终回复从临时上下文返回纯文本时也会丢失它。

现在共用一个纯解析/授权边界，前台、工具即时回复、自主发言、持久任务及本地入口传递已验证的引用元数据。私聊恢复其同会话档案中的原始消息元数据，不从显示文本提取 ID，也不加入群聊共享池。

## 验证边界

离线回归使用实际插件入口、原生代理工具回路、自主控制器、Recorder 档案、最终发送器与 TaskEvent 适配器；仅模型和平台发送替换为本机合成记录器。检查实际输出链包含所选 `Reply(id=...)`、没有裸引用标记，同时覆盖跨群拒绝、伪造正文 ID、最新消息非自动引用、静默与内部草稿。

这证明源码链修复和原生消息组件的生成，不代表当前线上 QQ 已更新或腾讯端显示已验收。**未重启、切换或更新生产实例；真实 QQ 收发需另行授权验证。**
