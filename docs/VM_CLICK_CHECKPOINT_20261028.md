# 屏幕点击视觉检查点（2026-10-28）

## 现有问题与增量修正

线上旧版 VM 的预览与直接点击路由彼此独立；`click_confirm` 只用进程全局坐标和 120 秒时间，甚至允许请求覆盖 x/y，且不校验画面或实际鼠标命令返回码。独立的 `vm_click_text` 原先也可直接点击。它们不能证明模型看过标点，不能防止过期画面点错。原始 VM API 属于生产主机文件，保持原样，不能以插件变更冒充整个服务的安全升级。

插件增加唯一 `vm_click_gate.ClickGate`（每个原生模型回合一实例）：

1. `vm_click_preview(x,y,label)` 读取实际 PNG 截图像素，校验文件为预期截图目录中的普通文件、图片大小与坐标；在新的私有随机文件内画十字点并将其作为独立图像观察送进模型，返回随机一次性 ticket、坐标、宽高和未标点像素 SHA-256。仅返回路径或文字不算模型已看图。
2. 下一次含标点图像的模型请求成功返回后，才把对应 ticket 标记为模型已收到；图像转换失败或没有纳入视觉请求不能标记。`vm_click_confirm(ticket,x,y,screen_sha256,viewed=true)` 必须在同一模型回合再次调用，ticket、坐标、hash 和布尔确认一致，并在 60 秒有效期内。
3. 确认时再截屏，比较完整解码 RGB 像素和尺寸，只有原样才调用原 VM 鼠标动作一次；任何错误或不确定回执都消耗 ticket，不重试，以免重复点击。旧直接 `vm_click`、`vm_click_text` 和旧 VM 预览/确认入口从插件工具通道拒绝，不把未经视觉核查的坐标落到底层。
4. `vm_type(text)` 依然一次传入整段文字，不要求模型逐字符调用。既有记忆、任务、授权、发送回执边界保持原样。

## 实测与剩余限制

离线集成覆盖真实插件原生模型循环（用替代的截图/模型/鼠标操作以免操作线上屏幕）以及更换屏幕、假标点、复用 ticket、跳过视觉请求、同批次确认等失败路径。插件依据实际完成的含图模型请求标记 `observed`；但无法从服务端证明模型主观上识别正确目标，`viewed=true` 仍是模型的显式复核声明。此视觉检查点只覆盖插件经模型暴露的点击工具；原始 VM 服务端的 HTTP 路由与可执行脚本、浏览器脚本等独立能力仍可间接发起鼠标事件。尚未做真实屏幕可视化验收，不能声称已覆盖所有绕行路径或绝对免除截图与点击之间的物理竞态。进一步服务端统一收口需先把 VM API 纳入仓库、核对实际部署基线及完整能力回归，并走独立受控发布。

独立 QQ 的原生登陆、收发和功能等价验收仍未完成，不能作为此项插件改动的完成条件代用品。
