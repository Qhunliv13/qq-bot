## 兼容增量

- 新条目按现有 `global.facts` 数组尾部追加，并把规范化的 `structure` 持久写入，
  即使没有指定类型也保存 `unspecified` / `active` / `subject=null`。同一作用域
  的重复内容返回原有位置和 ID，不生成新条目；编辑在原位置更新，不重新排序。
  成功回执返回 `created`、`append_position` 和 `appended_at_end`，不能把去重说成追加。
  存储仍以临时文件原子替换完整 JSON 文件，并非逐行追加 JSONL 或原地追加文件字节。
- 唯一存储仍为现有 `memory/memory.json`，不迁移、不覆盖、不断开原来的历史与图片。
- `structure` 明确类型：`fact`、`preference`、`instruction`、`note`、
  `unspecified`；状态 `active` / `superseded`；主体是显式 ID 和可选昵称。
  旧记录只在读取时投影为 `unspecified`，不自动改写或猜类别。
- 每轮从持久文件读取当前可见条目，按类型在用户数据层单独归类；已 superseded
  的条目仍保留在存储和列表中，但不作为活动约定注入。正文、附件元数据及
  最小来源 ID 单独提供，不把图片 base64 和整份来源聊天重复塞给模型。
- 模型看到的记忆是带来源的非可信数据，而非人格／系统指令。
  明确的约定和偏好应结合当前用户意图与既有更高层约束使用；昵称、存储文字或
  主体字段不能取得管理员权限，不把本轮的转发／引用当作发言人亲自承诺。
- `remember` 可显式给本批真实 `source_message_ids`；未给则只标记整批上下文。
  非本批 ID 拒绝且在抓图片和写盘前检查。保存回执包含真实持久 ID、类型和文字；
  重复内容返回 `created=false` 与既有来源，避免口头称“新记住了”。
- `facts_edit` 可只改结构不覆盖正文／图片；省略 structure 保留原分类。
  标记 superseded 不删除来源、图片或 ID。编辑和新建都检查当前事件／既有范围权限。
- 修复同一文字跨私聊与公开群去重导致返回隐藏私聊 ID 的问题；相同
  私聊空间内重复依然去重。移除达到 2000 条时自动淘汰最早条目的数据损失路径。
