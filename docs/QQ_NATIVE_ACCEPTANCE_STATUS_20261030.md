# Independent native QQ acceptance status — incomplete

This is a status record, not a completion certificate or a substitute for actual
login and feature-preservation acceptance. Production has not been cut over,
stopped, uninstalled or supplied to the lab as copied session data. No fresh
production uptime measurement is asserted by this record.

## Evidence established

- [Prepared native observation](qq-prepared-fsize-control.md): real native binding,
  preparation and initialization, 1/5/8-second timer dispatch, connecting/disconnected
  callbacks under an account-free offline profile. No connected/authenticated result.
- [Backend composition](QQ_NATIVE_BACKEND.md): explicit login/session/message
  controllers, disposal and identity checks, uncertain sends without automatic
  retry. Most composed session/message behavior is covered by substituted native
  boundaries, not real account traffic.
- [Network primitives and kernel checks](QQ_NATIVE_EGRESS_BOUNDARY.md): exact-address
  policy, numeric connector, real offline IPv4/IPv6 socket behavior, namespace-only
  kernel packet drops, and actual nested-offline slirp startup/readiness/retirement.
  Installing tools and passing those checks does not itself establish safe external
  QQ connectivity.
- [Pointer implementation](VM_POINTER_RUNTIME.md): marked path previews, model-image
  observation, single-use confirmation, coordinate/dimension/pixel checks and worker
  start expiry handoff. Adapter remains default-disabled. Whole-text input transport
  is implemented, but backend paste/real-desktop acceptance remains unverified.

## Outstanding completion requirements

1. Integrate a controlled external exit with route/interface-aware host-owned public
   address and LAN exclusions, private gateway/DNS handling and bypass tests. A frozen
   destination list is not proof of all routing or DNS behavior.
2. Present a genuine QR through a private owner channel and complete the user's
   independent test-account authentication. No QR login has been completed.
3. Supply complete session configuration from authorized native sources, establish
   real post-start session readiness, connect the independent transport to the bot's
   unified event/action core, and verify sustained send/receive with no NapCat proxy.
4. Validate all retained personal-QQ capabilities, media/events/actions and data/config
   compatibility. Existing request journals, permissions, memory, tasks and send
   confirmation must remain effective. Unit-test counts are not parity evidence.
5. Establish exclusive GUI capability ownership across input channels; raw execution
   and browser evaluation are not fully mediated by the preview gate. Validate actual
   desktop actions, image delivery, stale-screen rejection, release/cancellation,
   bulk text input and installer/runtime setup before enabling the adapter.
6. Any production migration requires separate explicit user authorization, baseline
   and backup verification, a reversible deployment and live acceptance. Consent to
   use a test account or install lab packages does not authorize production cutover.
