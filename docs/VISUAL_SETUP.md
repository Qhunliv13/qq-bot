# 不懂代码也能部署：创建你的第一个 Bot

本页面向第一次接触 Bot 的人。**不需要写代码，也不需要知道 Agent 是什么。**这是完整版本，聊天、持久记忆、任务和工具能力不会被删减。QQ 接入是后续可选步骤，不会自动登录账号。

## 先准备什么

- 一台可以联网、允许安装运行组件的电脑。首次下载与构建需要时间、内存和磁盘空间，不是离线便携程序。
- 模型服务商提供的 **服务地址（Base URL）／模型名称（Model ID）／服务密钥（API Key）**。模型请求可能收费；本项目不捆绑作者的账号、服务、密钥或充值入口。
- Windows 完整版仍需要 WSL2、Linux 内 Python 与 Docker / Compose。图形入口会解释并检查；需要安装时先征求同意，不强制重启。Linux 需自行准备 Python 3.10+、Docker 与 Compose v2。

> 如果你只需要不含 QQ、工具、记忆和任务的原生文字聊天，可选 [Windows 极轻量版](WINDOWS_LITE.md)。本向导不会自动降级成 Lite。

## 打开界面

**Windows：**完整解压下载的仓库，找到根目录的 [install.cmd](../install.cmd)，双击。先出现中文欢迎窗口；电脑已有多个 Linux 环境时用下拉框选择。缺少组件会弹出安装确认，拒绝即可安全退出。

安装 WSL 可能需要 Windows 管理员批准与重启；按系统提示完成后，从开始菜单打开 Ubuntu 完成首次用户名与密码设置，再次双击同一入口。环境组件安装期间保留启动窗口，进度可能仍由系统安装器／终端显示。环境可用后，浏览器自动打开本机部署向导。

**Linux 桌面：**在解压目录运行一次 `bash ./install.sh`，自动打开同一浏览器向导；高级用户可以继续用显式 `up` 等命令。无桌面的远程服务器不会自动开放公网安装页；参见 [Linux 说明](LINUX.md)。

## 网页上的五步

### 1. 准备好了吗

点 **检查 / 重新检查环境**。检查不调用模型、不发送 QQ 消息，也不改动其他服务。

如果未通过，Windows 先打开 Docker Desktop 并等待启动，再允许所选 Linux 环境使用 Docker；Linux 确认 Docker 与 Compose 已可用。处理后再点检查。

页面顶部独立显示四层状态：**运行环境／Bot 程序／模型回复／QQ 连接**。前一层通过不代表后一层已通过。

### 2. 连接模型

| 输入框 | 如何填写 |
|---|---|
| 服务地址 | 粘贴服务商给的 HTTP(S) Base URL，保留其要求的路径；不是网站首页，不要带完整 `/chat/completions` |
| 模型名称 | 粘贴服务支持的完整 Model ID，不是自己给 Bot 起的名字 |
| 服务密钥 | 粘贴 API Key，不是 QQ 密码；密码框默认隐藏，不要截图分享 |

填错时会显示对应项目的中文提示，已输入内容保留。密钥不会出现在网址、浏览器存储或运行日志；保存时进入此安装的本机私有配置，不进入 Git。

### 3. 创建 Bot

**名字与角色说明可留空。**想命名时可写类似“你叫小星，帮助我整理日程，回答清晰友好”的设定；不会强制猫娘、客服或固定人设。

展开高级设置才需要填写 QQ 管理员；留空不会授予任何 QQ 账号管理权限。多个 QQ 号用英文逗号分隔，不用填 QQ 密码。

点击 **保存并准备启动**。这只为当前专用目录创建一个 Bot；不会迁移旧数据、接管其他容器或代登录 QQ。重复打开不会要求重新填密钥，也不会覆盖原配置。

### 4. 启动与试聊

点击 **启动 Bot**。首次联网下载、构建可能较慢，保持启动窗口与网页打开。页面显示当前操作状态；等待完成，不要反复点击。

“Bot 程序已验证”后可填写一句不含私密信息的测试消息，阅读并勾选费用／执行确认，再点 **发送一次试聊**。它调用的是刚启动的完整 Bot，不是另一个 Lite 对话引擎。完整 Bot 具有工具能力，因此只输入愿意让它执行的内容；首次建议用页面预填的无外部操作测试消息。

- 收到实际回复，才显示模型回复已验证。
- 一次点击只发送一次，不自动重试。断开、报错或没有收到回复时，不代表模型一定未执行／未计费。
- 本机试聊会进入同一 Bot 的本地历史；不伪造 QQ 送达。
- 停止按钮需要再次确认，只停止所选 Bot，保留配置与聊天记录。

### 5. 开始使用

最简单的选择是 **打开网页聊天**。需要登录时，点击 **查看初始登录信息**，确认后在本页临时显示账号密码；30 秒后隐藏。请不要截图或旁观展示。若已在完整控制台改过密码，请使用新密码，向导不会重置它。

完整控制台保留模型、平台、任务、工具等高级页面。后续模型配置在控制台管理；首次向导不会重复覆盖它。**本向导保存的角色设定由安装的私有配置提供**，不是控制台角色数据库；不能假定在另一处改角色就会覆盖它。需调整时参见 [配置边界](CONFIGURATION.md)，先备份再受控修改，不公开私有文件。

## 想把 Bot 连接到 QQ

本次向导会明确引导入口，但**不会打包或代登录 QQ / NapCat，也没有完成独立原生 QQ 登录后端**。

1. 先在第四步确认模型可回复。
2. 在第五步打开 **消息平台设置**，选择适合自己的 QQ / OneBot 连接方式。
3. 按对应平台说明准备外部客户端／服务、登录账号并配置通道。不要把别人的 QQ 会话复制进来，不要公开无鉴权接口。
4. 在真实 QQ 中给 Bot 发一句话，确认实际收到回复。只有这样才完成 QQ 验收。

本地默认 OneBot 端口只映射到宿主 loopback；其他容器的 `127.0.0.1` 不是宿主机。需要连接跨容器服务时按 [快速开始的 QQ 步骤](QUICKSTART.md#可选外接-qq)安排地址与令牌。

向导不会把“已保存／已启动”冒充“QQ 已连接”，QQ 状态保留尚未验证。实际 QQ 登录和发送必须独立验收。

## 以后怎么用

- 再次双击**同一个入口、选择同一个 Linux 环境**，回到该 Bot 的启动管理页，无需重新填写。
- 关闭浏览器不停止 Bot；退出安装窗口会关闭向导，但不会停止已经运行的 Bot。
- 网页刷新不保留临时授权。请从安装窗口重新打开；Windows 可以关闭向导后再双击同一入口，不会重置数据。
- 不要分享带授权片段的安装链接。向导只绑定本机回环地址，不要改成公网监听。
- 不会自动升级、覆盖已有不同版本插件或迁移生产数据。原高级命令仍保留，详见 [Windows](WINDOWS.md)／[Linux](LINUX.md)。

## 验证说明

界面及其浏览器自动化使用临时安装目录、模拟运行时／模型回复测试，包含真正的本机 HTTP 与 Chromium 页面交互；这不等于真实 Docker 构建、付费模型或 QQ 登录已经通过。实际验收边界继续以 [部署验证记录](QUICK_DEPLOY_VERIFICATION.md) 为准。
