# 跨群记录按需读取修复（2026-10-28）

## 现场与根因

只读检查发现生产插件为 `7af432c`，QQ 在线、AstrBot active；用户指定群的归档存在，
当时包含 206 条 JSONL 记录。本修复没有清空归档或另建跨群记忆库。

公共群记忆一直是一个按时间合并的共享窗口，默认 240 条，缓存对齐最多多 29 条。
活跃群可能挤掉另一个较早群的全部记录。原覆盖元数据不列出归档群号，而历史搜索
只接受关键词，不能只给目标群号读最近记录。模型由此可能把当前窗口没出现的内容
误当成没有发生；这是证据可发现性与读取能力的缺口，不是证明所有错误回答的唯一原因。

## 增量修复

- 共享窗口的 coverage 增加 `archive_scopes` 和 `returned_scopes`，区别归档中有哪些群
  与当前窗口实际包含哪些群。保留原时间线、来源、预算和缓存对齐，不强行给各群分配配额。
- `history_search` 指定可见 `scope` 时可省略 `keyword`，读取该群的最近历史；仍可关键词
  检索。返回 `coverage` 的实际条数、限制和是否还有匹配记录。不指定 scope 的空检索
  不会变成全库倾倒。档案不代表实时群成员状态。
- 新只读工具 `qq_group_inspect` 按明确群号查询原生群信息和成员列表，分页展示。它通过
  现有认证桥调用 `get_group_info` 和 `get_group_member_list`，不发送消息、不改变事件来源。
  只有原生列表中每个成员都有明确布尔 `is_bot` 才统计该列表的 bot_count；否则返回未知，
  不凭昵称、bot 后缀、最近发言人数或字段缺失猜测机器人总数。
- 群记录共享仍仅针对公共群；不能利用猜测私聊 scope／路径或事实 ID 获取他人私聊。
  不设置特定群号、机器人名称、固定答案或强制工具调用规则。

## 能力边界

`archive_scopes` 是已有公共归档清单，不是 QQ 已加入群清单；`returned_scopes` 只表示
这次窗口中的群。列表中的人数是 API 返回的成员条数，不自动证明 QQ 返回完整名单。
普通个人 QQ 机器人可能没有可靠原生 bot 标志，因此“该群有多少 bot”仍需要可验证的
成员属性或历史证据；没有证据时不能再断言“只有自己一个”。

验证包含旧群被 300 多条其他群消息挤出的回归、明确群号无关键词读取、覆盖元数据、
来源保留、私聊隔离、原生响应验证和成员分页。合成网络边界测试不冒充真实账号 bot
识别验收。部署状态以受控发布结果及版本核验为准，不凭本说明推断已经上线。
