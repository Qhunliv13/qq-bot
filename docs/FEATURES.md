# 功能细节与实现边界

本页保留原根 README 的详细能力说明、技术入口和验证限制。第一次使用请先读 [快速开始](QUICKSTART.md)；本页不是执行生产迁移、实验接入或工具探针的授权。

## 选择运行版本

| 版本 | 平台与启动 | 包含内容 | 不包含 |
|---|---|---|---|
| 完整 Linux | Linux + Docker Compose，`python3 tools/bootstrap.py up` | 内嵌 AstrBot、本地入口、插件能力与独立状态 | 默认不安装或登录 QQ |
| 完整 Windows | Windows + WSL2，双击 `install.cmd`（复用 Desktop 或 Linux Engine） | **复用同一** Linux 安装器和完整容器，不另起一套核心 | 不是原生 Windows QQ；需要 WSL 与 Docker |
| Lite 文字版 | Windows / Linux，`python tools/lite.py --system-file persona.txt --interactive` | 仅 Python 标准库和已有模型 HTTP 适配器，进程内最多保留可配置轮数 | 不提供 QQ、AstrBot、工具、持久记忆、后台任务或网页面板 |

分别参见 [Windows 操作说明](WINDOWS.md)与 [Lite 操作说明](LITE.md)。这三个入口均不接管现有生产实例；Lite 不是删减生产配置，也不承诺处理无标记的模型内部规划。首次安装需用户自己的模型地址、模型名与凭据；真实 QQ 登录与独立原生 QQ 接入仍未完成。

### 保留全部能力的轻量请求模式

完整运行时另提供可选的[工具按需展开模式](TOOL_PROFILES.md)：`tool_profile.mode=light` 只减少初始工具定义，使用已有发现工具逐步展开，工具、权限、记忆、任务和数据不删除。默认 `full` 保持全部工具定义；**现有生产部署保持全量工程化与既有功能全开，不自动改为 light 或 Lite**。按需发现可能增加模型轮次，不能承诺模型行为、总费用或延迟完全相同。

## 当前能力与边界

- **共享群记忆**：已记录的群聊按时间合成一条共享上下文，实际模型窗口按序列化字符长度预算选择，不再以 240/120/2000 条作为记忆上限。默认上下文预算 600000 字符，可在外部 settings 的 context_memory.max_context_chars 调整；不是模型 token 容量的猜测。扣除固定请求成本后，可用聊天区按60%原文、40%摘要/归档分配；长度溢出的旧证据走无工具增量摘要，checked 落盘并注入后续请求，失败保留原始归档供检索；原始 JSONL 归档不删除，检索 API 的显式条数分页不是记忆保留政策。保留群、发送者和消息来源。私聊不进入共享群时间线。历史可按关键字检索，不是向量检索；上下文窗口不代表永久记忆容量。群间共享意味着跨群内容可被读取，部署前应确认使用范围。
- **提示词与缓存**：人设原样保留，附加层仅描述来源和传输协议。工具观察在请求数据中先于共享历史，以便观察未更新时跨历史追加／滚窗复用其前缀；观察更新或切换会话时可能损失历史前缀，实际收益依流量而定。实际历史不再为固定条数的缓存对齐牺牲记忆长度；按长度裁选保持原始时序，摘要独立标为有损模型数据，归档与检索不受影响。当前消息与时间等易变数据后置；仅调整 JSON 键顺序，协议 v1、解析后的完整字段与历史顺序不变。工具回执关联原始输入，不重复嵌入整份上下文预览。实际命中以提供方 `cached_tokens` 为准，字节前缀复用不等于缓存命中；图片、晚到的旧时间戳或同秒跨群记录排序变化仍可能打断前缀，不承诺固定命中率。
- **原生工具**：工具目录包含 110 个唯一 schema，覆盖记忆、历史、QQ 操作、文件、虚拟机、任务、技能和委派。目录存在不代表当前账号、上游模型或 NapCat 实现支持全部操作；写权限与目标范围在执行时校验。
- **事实管理**：事实带稳定编号、来源和自由分类标签。`facts_classify` 按编号批量替换或清空标签，`facts_categories` 查看可见类别统计，`facts_delete` 按精确编号删除；指定编号时不扩展为关键词批量删除。保存失败不报成功，删除后的编号不分配给新事实。只读子智能体可查事实并返回分类／删除建议，由主智能体执行当前会话授权的修改。
- **消息转发与复制**：`qq_forward_messages` 按消息 ID 或最近条数选择真实群消息，支持原群／跨群、合并／逐条转发；合并引用原消息保留发言人，逐条使用原生转发。`qq_copy_message` 保存原消息组件，`qq_paste_message` 在授权目标群以机器人身份粘贴；剪贴板按当前会话隔离，富消息能否发送仍取决于平台。发送使用稳定操作 ID 防重；逐条转发的原生空回执只证明受理，不冒充已确认送达。
- **QQ 申请**：原生入群与好友申请事件单独持久化，不作为空白聊天交给模型。所有者可查看已采集的申请并明确同意／拒绝；审批绑定原生请求与账号，持久防重，未知结果不自动重试。平台受理不等于已入群或已成为好友。当前 NapCat 没有已注册的主动加群、回答入群验证题、主动加好友接口，对应三个工具明确返回能力不可用，不执行替代操作。
- **公开回复**：普通前台 final 需要明确的结构化公开正文；无工具调用的未标记文本先作为非公开草稿，最多用原始上下文请求一次无工具 final，失败则不发送、不按措辞关键词硬裁剪；独立 `reasoning_content` 不并入正文。自主观察的 final、以及同轮已通过 `reply_now`、有原生回执的 `qq_send`（包括只 @ 不带正文），或插件媒体通道（如 `send_shot`、`send_sticker`）在同一会话成功发送后的 final 默认作为内部草稿，使用已有 `delivery=new` 显式发布；`reply_now` 等发送工具仍可多次调用，默认不结束回路，`finish=true` 可显式结束。主动 @ 不强制补发“已提醒”等说明，模型可沉默，也可显式再说；其他目标会话的回执不会抑制本会话回复。规则区分发布动作与完成文本，不比较措辞或相似度。发送档案保留原生消息 ID、输入与引用来源、目标会话和时间，未确认回执单独标记。协议与局限详见[思考与公开输出边界](REASONING_OUTPUT_BOUNDARY.md)。
- **排队执行**：消息入口完成必要采集后入队返回，不等待整轮模型／工具／发送。受跟踪的会话 worker 取得共享执行锁后才快照待处理消息；等待期间同群消息组成下一批，当前正在执行的批次不被改写。群权限在出队和发送时复核，热重载排空已有工作。模型、媒体读取、执行锁和重载就绪等待仍会带来延迟，不保证固定响应时间。
- **主动观察**：持久化调度提供思考机会，不是强制发言。默认机会间隔 600 秒且可调整，轮询间隔 30 秒；只向已观察到的真实会话发起操作，并受群策略和执行忙闲影响。
- **委派 worker**：异步运行只读原生工具子任务，支持查看、排队补充指令和中断；结果回执按会话范围保存。补充指令不打断正在进行的模型请求；进程重启后不自动恢复失去执行者的 worker。
- **后台任务与回执**：任务持久化、执行前认领，失败暂停；未确认结果的认领不自动重试。后台轮次使用独立的任务输入，不继承前台待处理消息；任务结束、暂停或认领失效后，不再请求下一轮模型或发送滞后的最终回复。当前任务上限 50 个、最短间隔 30 秒，约每 25 秒检查到期任务并等待执行锁；不是准点交付保证。QQ 消息发送依赖平台消息 ID 回执，不能以模型文本、HTTP 成功或服务存活替代送达证据。

模型和工具仍受各自请求超时、可配置回合/整轮预算、平台权限与外部服务可用性约束；不承诺无限执行、全部工具可用或测试覆盖真实部署的所有路径。

## 目录与工具

| 路径 | 用途 |
|---|---|
| [`plugin/`](../plugin/) | AstrBot 插件与原生工具、记忆、排队、任务和回执实现 |
| [`tests/`](../tests/) | 离线单元、契约与集成适配测试 |
| [`tools/`](../tools/) | 探针、策略管理、发布检查与受控应用工具；各文件的参数和副作用需单独确认 |

`tools/*_probe.py` 等探针的联网、读取和发送范围并不相同，执行前先读脚本；不把所有探针统一视为只读。`tools/validate_release.py` 检查发布文件；绑定原作者服务器的旧发布工具已移入[个人运维归档](../trash/20261030-personal-operations/README.md)，不作为通用部署入口。新安装不带个人所有者/群默认值，模型、地址和数据目录由[外部配置](CONFIGURATION.md)决定。

## 本地检查与配置

```bash
python -m pytest tests -q
python -m compileall -q plugin
```

这些命令验证本地源码，不代表实际 QQ 登录、模型请求或生产部署已通过。全新实例使用安装器配置模型与隔离数据；内嵌 AstrBot 不需另行克隆，QQ 接入仍需独立配置。容器保留 `/root/higan` 内部路径以兼容现有模块，绑定到所选外部数据目录；不要直接迁移或覆盖旧数据。

密钥、密码和令牌仅从私有运行配置或相应环境变量提供。不要提交运行数据库、聊天档案、图片附件、工具观察文件、会话资料或 Dashboard / 上游凭据；非秘密路径与账号标识也应在部署前复核。

## 独立 QQ 接入重写（未完成）

目标是保留现有个人 QQ、全部功能与数据，完全移除 NapCat 运行依赖；当前已建立依赖清单、离线覆盖检查，以及独立的[事务／事件传输基础模块](../qq_transport/README.md)；**尚无可替换的独立原生 QQ 后端**。详见 [实施边界与验收计划](QQ_TRANSPORT_REWRITE.md) 和 [最小已观察契约](qq-transport-required.json)。运行 `python tools/qq_transport_parity_audit.py` 可审查声明覆盖，结果不授权生产切换；现有接入保持不变。

## QQ 作为能力，而非唯一入口

[原完整实例的本地入口](LOCAL_FULL_CORE.md)在同一个现有 bot 上接入 root-only Unix socket，复用人设、模型、工具、记忆、任务和全局队列；不再要求请求先来自 QQ。QQ 登录和全部旧状态不迁移，QQ 仍作为原生能力保留；当前宿主仍是 AstrBot，不宣称已移除其生命周期。[简单独立 harness](BOT_HARNESS.md)继续供显式嵌入使用，不另建第二套生产状态。[核心解耦设计](BOT_CORE_DECOUPLING.md)仅保留为后续参考。
