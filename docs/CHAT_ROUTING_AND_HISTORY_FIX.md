# 聊天入口及历史检索修复（2026-10-28）

## 用户要求

关闭所有聊天指令和权限不足提示；单独 `@` 使用原 bot 的人格与上下文，不能进入
宿主默认问候；单独 `/` 不能当作 `@`；修复历史检索中的次数、来源和时间证据问题。
模型工具、长期事实、图片事实、任务、人格和 QQ 登录不属于被关闭的聊天指令。

## 入口归属

原始 AstrBot `handle_empty_mention` 在 bot 插件之前处理单个 At，使用专门的默认问候
提示且 contexts 为空，随后安装会改写并重新入队消息的等待器。单个唤醒前缀也能进入
这条路径。框架 WakingCheck 另有权限不足文案，与默认问候是两个独立来源。

本次不修改内嵌或生产的 AstrBot 原始源码，不放开管理员权限：

- 通过受认证的原生配置 API 设置 `platform_settings.empty_mention_waiting=false`，
  `platform_settings.no_permission_reply=false`，`disable_builtin_commands=true`，
  `wake_prefix=[]`。保留其他配置；原配置及数据库先备份，临时 config scope key 用后撤销。
- 取消本插件三个聊天命令的注册，保留原函数和模型工具实现。生产当前只加载本插件与
  原始内置插件时，这覆盖现有聊天指令。未来新装插件仍须单独审核其命令入口。
- 本插件消费以 `/` 开头的聊天输入，不交回宿主命令或默认模型管线，不把它当作 self At。
- 唤醒判定复用规范化的顶层 At 消息段，不再信任可同时代表指令的框架 wake 布尔标志。
  私聊仍是独立直接输入，引用里的 At、其他人的 At 不成为当前直接提及。

关闭的是聊天侧命令注册和唤醒前缀，不是 API、WebUI、本地操作入口或模型工具权限。
权限不足仍会拒绝，只是不再发送用户要求关闭的提示；不把任何截图中的 ID 加为管理员。

## 历史检索

- 原搜索没有去除相同 scope＋原始消息 ID 的重复归档行，且没有翻页；现在同一个真实
  消息只计一次，保留第一归档。无真实 ID 的历史行、不同群或不同 ID 的相同文字不合并。
- 增加 `offset`，覆盖元数据报告本页位置和下一页；不能把一页命中条数当作完整总数。
- 仍可命中引用文字，但返回的是实际发出引用的消息及其作者／ID，不能据此认定又发送
  了一条相同的合并转发。命中条数不等于相同转发次数，机器人复述也不等于用户再次转发。
- 规范化记录现在仅在源事件真实提供时保留 `native_time`、`time_source` 和顶层
  `forward_ids`。不从截图、正文或引用推断新时间、来源或转发身份。
- 历史行的 `ts` 仍为归档写入时间，不能伪称 QQ 原始发送时间。旧记录缺少原生时间或
  转发 ID 时不回填、不编造；新增证据仅对收到后的消息生效。
- 排序只使用有限数值时间，布尔、NaN 和无穷大不再影响时间排序。

验证包含入口消费、不伪造 At、管理员边界、配置精确变更、密钥撤销、重复 ID／引用、
跨群隔离、翻页和原始事件元数据保留。源码／合成事件测试不等于真实模型对话验收；
上线是否完成以发布结果为准。
