# 事实条目中的图片

长期事实仍由原来的 `Memory` 和 `memory/memory.json` 保存。现支持文字＋图片、
纯图片以及原有纯文字记录，不新增独立事实库，不自动把收到的图变成长久记忆。
现有来源、自由分类、scope 和 ID 保持原有语义，图片与正文具有相同可见性。

## 使用工具

- `remember`：`text` 和可选 `images` 数组。数组中填已选图片引用；沿用原有图片
  转换链路读取 HTTP、本地路径或 data URL，在保存前规范化内容。任一图片获取或
  验证失败则不保存半条事实。纯图片时 `text` 可为空字符串。
- `facts_list` / `facts_search`：增加 `images` 元数据数组，包含从 0 开始的 `index`、
  MIME 和字节数，不把 base64 放进常规工具结果。搜索仍匹配文字，并非图像相似检索或自动 OCR。
- `facts_read_image`：给出事实 `id` 和可选 `index`（默认 0），只读取当前可见条目的
  对应图片。原生工具循环将实际图片送到下一轮视觉输入，不向 QQ 发图。
- `facts_edit`：省略 `images` 保留旧图；传 `[]` 清空；传新数组替换。修改后必须
  至少有文字或图片，不得通过猜测别的私聊事实 ID 读取或修改附件。

示例工具参数：

```json
{"text": "这张图是设备接线记录", "images": ["当前已见图片的引用"]}
```

```json
{"id": "实际返回的事实编号", "index": 0}
```

不要把示例占位文字当作有效图片或真实事实编号。

## 存储和验证边界

图片内容保存在事实的 `images` 字段，使用规范化的 base64 data URL。重启后仍保留
同一份内容；后续原链接失效不影响已经成功保存的图片。支持 PNG/JPEG/GIF/WebP，
按内容签名校正 MIME，每张最多 4 MiB，与原有单图读取上限一致。签名检查不是完整
像素解码、文件安全扫描或对图中内容的事实认证。

图片随原记忆文件备份；base64 会使文件体积增大约三分之一。普通列表和工作上下文
不会自动塞入全部图像，避免每轮请求膨胀。仍需在现有事实数量、磁盘和备份管理下
使用；未新增自动清理图片、压缩图片或改写历史数据的任务。

相同文字＋相同规范化图片去重并保留第一来源；相同文字但不同图片可保存成不同事实。
文字编辑默认不丢附件。写盘失败恢复内存状态，不返回成功。

`wp_fact_move` 的目标唤醒人记录仍是旧文本格式；带图事实会明确拒绝移动，而不是
复制文字后删除唯一的图片。这次只扩展通用长期事实，不冒称唤醒人记录也支持图片。

本次不改变 QQ 登录、NapCat、模型供应商、人格或现有生产版本。代码测试和本地
存储／工具集成验证不等于已经部署或完成真实线上图像模型请求。
