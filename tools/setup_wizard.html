第一步 · 准备

不用懂代码，也能创建 Bot

Bot 就是你自己的聊天助手。这里帮你完成安装和启动；无需理解“Agent”、容器或命令行。

  1. 检查电脑是否具备运行条件。
  2. 填写模型服务商提供的地址、模型名称和密钥。
  3. 选择角色，保存并启动，然后发一句话试试看。
这是完整版：聊天、记忆、任务与工具能力都保留。初次安装需要联网下载运行组件；运行时也可能产生模型服务费用。Windows 的 Linux 运行环境与 Docker 仍是必要条件，不会偷偷切换成精简版。
检查失败怎么办？

Windows：打开 Docker Desktop，等待它启动，在设置中允许这次选用的 Linux 环境使用 Docker。Linux：请先安装并启动 Docker 和 Compose。已有程序不会被卸载或替换，检查按钮不会发送任何聊天消息。

如果刚刚安装了 Windows 运行组件，可能需要按系统提示重启电脑，再次双击安装入口即可继续。

第二步 · 连接模型

把模型服务的资料填在这里

模型负责理解你的话并生成回答。下面三项通常在你使用的模型服务商网站的“API / 开发者 / 密钥”页面找到。

这是接口地址，不是网站首页。保留服务商要求的路径；不要填完整的 /chat/completions 请求地址。按服务商标注原样填写，不是自己给 Bot 起的名字。相当于访问模型服务的密码，不是 QQ 密码。不会写进网址、浏览器存储或日志；请勿分享截图。密钥将保存在此安装的本机私有配置中。
没有这三项资料时，请先向你的模型服务商获取。向导不捆绑账号、充值入口或默认付费服务，也不会自动试扣费用。

第四步 · 启动与试聊

让 Bot 运行起来

首次启动需要下载并构建运行组件，可能持续较长时间。请保持电脑联网并保留安装窗口；进度会在此页面显示。

“已启动”仅代表本机完整 Bot 已可访问，不代表模型或 QQ 已验证。停止只影响这里选中的 Bot，配置和聊天记录都会保留。

发一句话，确认它真的会回复

这会调用刚启动的完整 Bot，并使用你的模型余额。它具备完整工具权限；只输入你愿意让它执行的内容。不会向 QQ 发送测试消息。



第五步 · 使用
选择在哪里使用 Bot
先从网页聊天开始最简单。QQ 是可选连接，需要额外完成账号和消息通道设置，不会在你不知情时登录。
推荐：先在网页里聊天
打开完整控制台，用初始账号登录，再进入“聊天”。完整模型、角色、任务、记忆、工具与平台管理仍在原控制台中。
打开网页聊天 ↗打开完整控制台 ↗
登录信息只在你确认后显示；若已在控制台修改密码，请使用新密码。页面刷新后请从安装窗口重新打开授权页面。
可选：接入 QQ
  1. 先完成上一步试聊，确认模型能回答。
  2. 打开完整控制台的“消息平台”，选择添加适合你的 QQ 连接方式。
  3. 按平台页面说明准备相应的 QQ 客户端 / 服务，并完成登录与连接。当前安装包不会自动安装或代登录 NapCat，也不包含独立原生 QQ 登录。
  4. 在 QQ 中主动给 Bot 发一条测试消息，确认真实收到回答，才算 QQ 接入完成。
前往消息平台设置 ↗
此向导不会把“已保存配置”或“本机健康”冒充 QQ 在线。顶部 QQ 状态保留“尚未验证”；仅以你在实际 QQ 中收到的回复作为验收依据。
以后怎么启动、修改、停止？
再次双击同一个安装入口，回到这一个 Bot 的管理页，无需重新填写密钥。启动、环境检查、停止都在第四步。关闭浏览器不会停止 Bot；停止 Bot 请使用本页按钮。退出安装窗口会关闭向导，但不会停止已启动的 Bot。
模型与平台等后续配置，请在完整控制台里修改。这里是首次部署向导，不会覆盖运行中的控制台配置。原有命令行高级选项继续可用。


设置只保存到选中的本机安装。不会改动其他 Bot、现有服务或生产账号。
