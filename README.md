# 群聊 AI 插件（AstrBot）

一个让大模型**自己判断该不该在群里接话**的 AstrBot 插件。它不是"随机概率回复"，
而是把判断交给模型，并由插件提供判断依据（谁在跟谁说话、有没有正在进行的对话）。

除对话外还支持：**看图**（含动图多帧）、**表情包自管理**（收集/挑选/发送/改标签/丢弃）、
**联网查询**（搜索 + 打开网页读正文）、**认人**（区分管理员与普通群友）、
**群成员变动感知**（加群/退群）。

> 只依赖 AstrBot 与一个 OpenAI 兼容的对话接口；不绑定任何特定厂商、角色或部署环境。

本仓库含两个插件：**`astrbot_plugin_group_ai`**（轻量群聊对话）与
**`astrbot_plugin_higan`**（完整人格 + 自带虚拟机，能截屏、上网、点页面、跑脚本、收发邮件与文件）。
两者可独立使用，也可一起装；区别见[目录结构](#目录结构)下面的对比表。

**两个插件的区别**

| | `astrbot_plugin_group_ai` | `astrbot_plugin_higan` |
|---|---|---|
| 定位 | 通用群聊对话插件，轻量 | 完整人格 + 自带虚拟机（截屏/上网/点击/执行） |
| 依赖 | 只需 AstrBot + OpenAI 兼容接口 | 另需一个虚拟机侧的 HTTP 服务（默认 `127.0.0.1:18003`） |
| 适合 | 想快速上手、只在群里聊天 | 想让她真的动手做事（看屏幕、点网页、收发文件） |

## 安装

1. 把 `astrbot_plugin_group_ai/` 整个目录放进 AstrBot 的 `data/plugins/`。
2. 在 AstrBot 里配置一个 **OpenAI 兼容的 Provider**（对话模型需支持图片输入才能用看图能力）。
3. 配置 **OneBot 平台适配器**（NapCat / Lagrange 等）。若用反向 WebSocket，
   由 OneBot 端主动连 AstrBot；插件本身只通过 OneBot 的 **HTTP 接口**读群/成员信息。
4. 重启 AstrBot，在插件配置面板里填[配置项](#配置)。
5. 群里 @ 一次机器人，确认能回。

**依赖**：AstrBot ≥ 4.x；`Pillow`（图片压缩与动图抽帧，AstrBot 环境通常已自带）。

## 配置

分两层，**代码里不写死任何具体部署的值**：

### 一、实例配置（`config.py` + `_conf_schema.json`）

在 AstrBot 的插件配置面板里填，落盘于 `data/config/astrbot_plugin_group_ai_config.json`。

| 键 | 类型 | 说明 |
|---|---|---|
| `owner_ids` | 列表 | 管理员（"主人"）QQ。留空 = 不区分身份，所有发言人都按普通群友对待 |
| `bot_name` | 字符串 | 机器人在提示词里的自称。留空用内置默认名 |
| `persona` | 文本 | 自定义人设正文。留空用内置的**通用默认人设** |
| `persona_file` | 字符串 | 人设文件路径。存在则优先于 `persona`（长人设建议用文件） |
| `target_groups` | 列表 | 只在哪些群工作。留空 = 所有群 |
| `member_watch_groups` | 列表 | 监听哪些群的成员变动。留空 = 不监听 |
| `onebot_base` | 字符串 | OneBot 的 HTTP 接口地址（拉群/成员名单用） |
| `web_enabled` | 布尔 | 是否允许联网查询（搜索/打开网页/搜图）。默认开 |

> **容器化部署注意**：OneBot 若跑在容器里，容器内的 `127.0.0.1` **不是宿主机**。
> 需要填宿主机的可达地址（例如 Docker 网桥网关），或让两者共享网络。

### 二、项目级调参（`main.py` 顶部常量）

这些是通用工程默认值，对所有使用者都成立；想改直接改常量（完整表格见
[`docs/CONFIGURATION.md`](docs/CONFIGURATION.md)）。

| 常量 | 默认 | 作用 |
|---|---|---|
| `MIN_REPLY_INTERVAL` | 30 | 非 @ 回复最小间隔（秒）。调小更活跃，调大更安静 |
| `MIN_WOKEN_INTERVAL` | 5 | **被 @ 时**的最小间隔。明确呼叫不该被大间隔挡住 |
| `MAX_REPLY_PER_MIN` | 3 | 非 @ 每分钟上限 |
| `MAX_WOKEN_PER_MIN` | 6 | 被 @ 时每分钟上限 |
| `REVIEW_IMAGE_MAX_SIDE` | 512 | 发图给模型前压到多少像素（**直接决定快慢**） |
| `REVIEW_TIMEOUT` | 25 | 单次视觉调用超时（秒） |
| `CHAT_TIMEOUT` | 45 | 单次生成回复超时（秒） |
| `GIF_MAX_FRAMES` | 4 | 动图抽几帧（只取首帧看不懂过程） |
| `MAX_CANDIDATES` | 5 | 挑表情包时给模型看几张候选 |
| `MAX_STICKERS` | 300 | 表情包库上限（超限按最久未用淘汰） |
| `MAX_STICKER_BYTES` | 4 MB | 单张表情包体积上限（字节） |
| `SEARCH_TOP_N` / `PAGE_FETCH_TOP` | 5 / 2 | 搜索取几条结果 / 打开几个网页读正文 |
| `MEMBER_WATCH_INTERVAL` | 60 | 轮询群成员名单的间隔（秒） |

## 模型可用的标记（工具调用）

插件用**方括号标记**实现轻量"工具调用"（比完整的 ToolSet 少一层接线，模型也容易学）。
标记兼容中英文方括号、书名号、圆括号与全角冒号：

| 标记 | 作用 |
|---|---|
| `[搜索:关键词]` | 联网搜索并**打开网页读正文**，然后把材料交回模型作答 |
| `[下图:关键词]` | 搜索图片 → 下载 → 发到群里（也支持 `[下图:头像 QQ号]`） |
| `[头像:QQ号]` | 直接发某个群成员的头像 |
| `[表情包:关键词]` | 按关键词模糊搜索 → **把候选图给模型看** → 它挑一张发出去 |
| `[删表情:关键词]` | 让模型主动丢弃无意义的图（**只移出索引，不删文件**） |

> 没被识别的标记会被整段去掉，**不会把标记当文字发出去**。

## 能力概览

### 回复决策

| 场景 | 行为 |
|---|---|
| 被 @ / 被引用 | **一定回** |
| 群里闲聊 | 模型判断该不该插嘴 |
| 别人在对话中（@ 了别人、引用别人的话、恰好两人一问一答） | 不插嘴 |
| 严肃话题（技术排查、交易、纠纷等） | 不插嘴 |
| 模型输出 `SILENT` | 表示这次不接话 |

插件会把**判断依据**一并交给模型（发言人身份、@ 了谁、是否有人在对话），
避免它凭空猜测。

### 看图

本条消息的图、被引用消息里的图、被问到的那个人的头像、群里最近出现过的图 —— 都会按需带上。
**动图会等间隔抽帧后横向拼成一张长条图**再交给模型，这样它能看懂"过程"。

### 表情包

- **收集**：群里出现的图会入库（按内容哈希去重），并用视觉模型打一句关键词描述。
  也可以把图片直接丢进 `data/stickers/`，插件启动时自动登记。
- **挑选**：按关键词模糊搜索候选，**把候选图连同标签一起给模型看**，由它选一张。
- **自管理**：模型可以修正标签（`标签N：新关键词`）、丢弃废图（`删N` 或 `[删表情:…]`）。
- **管理命令**：`表情列表`、`表情改`、`表情删`（仅管理员可用）。

### 联网

- **网页搜索**：Bing 搜索 → **并发打开前几个网页读正文**（只给摘要答不了"现在几点"这类问题）。
  部分站点会反爬（403），所以会多试几个、取成功的。
- **图片搜索**：Bing 图片搜索 → 下载 → 发出。
- **当前时间**：每轮提示词都会注入，问时间/日期**不需要搜索**。

### 认人与群成员

- 发言人身份由插件算好标注（`昵称（管理员/群友，QQ 号）`）；**QQ 缺失时不瞎标身份**。
- 机器人自己的头像：启动时拉取并用视觉模型描述一次，缓存后每轮注入（"自我认知"）。
- 群成员变动：轮询名单做 diff，把"加入/退出"写进群上下文。首次只建基线，
  不会刷"全员加入"。

## 设计要点（通用工程经验）

这些是实现中容易踩的**通用**问题，与具体部署无关，改代码前值得先读：

| 主题 | 要点 |
|---|---|
| **图片体积** | 原图 base64 后可达数 MB，一次视觉调用可能耗时上百秒 → **先压到几百像素**（"判断这张图合不合适"不需要原图），体积能降到约 1/10，耗时降一个数量级 |
| **本地图片** | 直接把 `file://` 交给 provider 往往取不到图 → 统一转 **base64 data URL** |
| **收到的图片** | 平台适配器通常把图片落盘，组件里是**本地路径**而不是 URL → 收集表情包时要同时处理两种形态 |
| **动图** | 只取首帧会看不懂"过程" → 抽多帧横向拼成一张图（只占一张图的 token） |
| **人设被覆盖** | 插件自己调 LLM 时传了 `system_prompt` 会**替换**平台的人设 → 必须自己把人设拼在最前面 |
| **拦截默认回复** | 若平台还有自己的默认回复流程，仅"请求不调用 LLM"可能拦不住 → 需要停事件并**自己直接发送** |
| **判断"别人在对话"** | 判据过宽（如"近期出现多个发言人"）在热闹的群里几乎永远成立，会把机器人变成哑巴 → 只认**恰好两人且交替发言** |
| **人称歧义** | "**我的**头像是什么"问的是**说话人自己**；若此时把机器人自己的头像发过去，模型就会答错 → 必须按问题解析"这是谁的图"并明确告知归属 |
| **人设示例会教坏语气** | 示例里出现刻薄措辞，模型就真会那么说 → 示例要给**好/坏对照**并列出禁止清单 |
| **频率限制要分档** | 被 @ 时若也套用"少说话"的大间隔，会出现"叫了不回" → 被 @ 用**独立的、更宽的**限制 |
| **容器网络** | 容器内的 `127.0.0.1` 不是宿主机；反向 WS 地址要写宿主可达地址 |
| **配置缺失** | 配置项缺失/类型不对/留空都不该让插件起不来 → 一律回退默认值并记日志 |

## 开发与维护

- **单一实现**：同一逻辑只写一处。实例默认值只在 `config.py`，提示词只在 `prompts.py`，
  日志前缀只用 `LOG_TAG`。
- **每个函数都要有 docstring**，说明**为什么**这么做，而不只是重复字面意思。
- **幂等**：写操作可重复执行（表情包按内容哈希去重、成员 diff 只报变化）。
- **不留死代码**：改完跑静态检查。
- **增量改动**：不要覆盖性重写大文件；小步改、每步可回滚。
- **拆模块的注意点**：AstrBot 以包路径导入插件，因此**相对 import 可用**（官方插件也这么写）。
  但拆的时候要留意：装饰器（如 `@staticmethod`）要一并处理、缩进层级会变、
  **把方法当值传递时没有括号**（如 `to_thread(self._fn, …)`），改名时容易漏。

静态检查（本仓库自带 `tools/lint_pyflakes.py`，不依赖 `python -m pyflakes` 入口）：

```bash
python tools/lint_pyflakes.py astrbot_plugin_group_ai
python -c "import ast,pathlib; [ast.parse(pathlib.Path(f).read_text(encoding='utf-8')) for f in pathlib.Path('astrbot_plugin_group_ai').glob('*.py')]"
```
